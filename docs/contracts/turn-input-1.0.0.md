- Owner: Chat Runtime

## Bounded baseline status and known limitations (CP-000R)

This contract is **accepted and implemented as a bounded baseline**. Base repository evidence:
`6477c1c`. Bounded implementation existed at base commit `6477c1c`. CP-000R documentation acceptance
becomes effective when the CP-000R commit is reviewed and merged.
CP-000R changed no field, no type, no validation rule, no schema, and no version of this contract. It
records truthfully what this 1.0.0 contract does and does not yet cover, and who owns the remaining
work.

| Known limitation | Owner |
| --- | --- |
| `TurnInput 1.0.0` intentionally carries **no identity and no authorization**. It does not carry a `SecurityPrincipalContext`. Trusted principal resolution and authorization binding occur in the runtime context and in the separate versioned security contracts. A first-class typed anonymous Guest principal does not exist yet (audit finding G-006), and Guest must never be represented through a fabricated `TurnInput` user identity | CP-001 with CP-002 |
| No typed binding to a pinned `VisibilityPolicyDefinition` revision or to an authorization request identifier | CP-001 |
| Client-supplied fields are untrusted input. Nothing on a turn input authorizes anything; authorization is resolved by the authorization layer only | Unchanged rule |
## Purpose

TurnInput is the immutable, validated input handed to the Chat Runtime after transport-level parsing. It carries the user message and the identifiers needed to correlate one turn. It carries no identity, authorization, security policy, normalized query text, provider objects, or model output.

## Fields

| Field | Type | Required | Default | Rules |
| --- | --- | --- | --- | --- |
| schema_version | literal string | no | 1.0.0 | only 1.0.0 accepted |
| request_id | UUID | yes | none | UUID version 4 |
| message_id | UUID | yes | none | UUID version 4 |
| conversation_id | UUID | yes | none | UUID version 4 |
| raw_message | string | yes | none | 1 to 32000 characters, not blank, no NUL |
| locale | literal string | no | fa-IR | only fa-IR supported |
| channel | literal string | no | web | only web supported |
| received_at | UtcDateTime | yes | none | timezone-aware, normalized to UTC |
| idempotency_key | UUID | yes | none | UUID version 4 |
| attachments | tuple of AttachmentRef | no | empty tuple | at most 10, unique ids, ordered |

AttachmentRef contains exactly attachment_id (UUID version 4) and version (positive integer). It intentionally carries no URL, path, filename, media type, credential, or raw content.

## Trusted versus untrusted origins

These origins are contractual documentation and are not enforced by validation.

| Field | Origin |
| --- | --- |
| request_id | generated by the server |
| received_at | generated by the server |
| channel | resolved by the server |
| conversation_id | validated by the server |
| attachments | resolved against trusted storage |
| message_id, idempotency_key | client supplied, format validated |
| raw_message | untrusted client data |

## Invariants

- The model is closed (extra=forbid), frozen, and validates defaults.
- raw_message is returned exactly as received: no trimming, no Unicode normalization, newlines and tabs allowed, Persian text preserved.
- Empty, whitespace-only, and NUL-containing messages are rejected.
- Timezone-naive received_at is rejected; aware values are converted to UTC and keep the same instant.
- attachments is an immutable tuple, at most 10 entries, unique attachment_id values, order preserved; null is rejected and a missing field becomes an empty tuple.
- Any role, permission, scope, token, secret, security-context, normalized-query, URL, or path field fails validation because it is an unknown field.

## Sensitive data

raw_message may contain personal or confidential user content and must be treated as sensitive untrusted data. Identifiers are opaque correlation values. No credentials, tokens, or secrets may appear in this contract; their presence alone is a validation failure.

## Retention

This contract does not authorize persistence. Storage and retention of any field are controlled by runtime, conversation, and audit policies that will be implemented later.

## Error semantics

Validation failure is represented by Pydantic ValidationError. API and domain error mapping are deferred to CONTRACT-004. No error envelope or custom API error type is defined here, and no user-facing message is produced.

## Compatibility

The model is closed, so any change to the accepted or serialized payload set is a major change.

- PATCH changes must not alter the accepted or serialized payload set.
- Adding, removing, or renaming a field requires a new major schema version.
- Changing validation rules or field meaning requires a new major schema version.
- Version 1.0.0 remains immutable once approved.
- Additive MINOR compatibility is not claimed for this contract.

## Valid example

```json
{
  "schema_version": "1.0.0",
  "request_id": "11111111-1111-4111-8111-111111111111",
  "message_id": "22222222-2222-4222-8222-222222222222",
  "conversation_id": "33333333-3333-4333-8333-333333333333",
  "raw_message": "gozaresh fani",
  "locale": "fa-IR",
  "channel": "web",
  "received_at": "2026-01-01T08:30:00Z",
  "idempotency_key": "44444444-4444-4444-8444-444444444444",
  "attachments": [
    {
      "attachment_id": "00000001-0000-4000-8000-000000000000",
      "version": 1
    }
  ]
}
```

Persian content is valid in raw_message and is preserved exactly; the example uses ASCII only for readability.

## Invalid examples

| Payload change | Reason |
| --- | --- |
| raw_message set to three spaces | blank message |
| raw_message of 32001 characters | exceeds maximum length |
| received_at set to 2026-01-01T12:00:00 | timezone-naive value |
| request_id set to 11111111-1111-1111-8111-111111111111 | not UUID version 4 |
| locale set to en-US | unsupported locale |
| eleven attachments | exceeds the attachment limit |
| two attachments with the same id | duplicate attachment id |
| attachments set to null | null is not an empty tuple |
| extra field role | unknown field, fails closed |
| extra field security_context | unknown field, fails closed |

## Non-goals

Identity, roles, permissions, security policy, normalized query text, prompt or provider payloads, model output, HTML or prompt-injection filtering, language detection, content moderation, storage metadata resolution, persistence, and API error mapping are outside this contract.
